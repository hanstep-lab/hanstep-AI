## 4. 판정 규칙과 지표 (측정 전에 정함)

판정은 ok / 위반 / 판정 불가(조건표 값 null) 셋이다.

| 조건 | 위반 | 판정 불가 |
|---|---|---|
| 추천 대상 | recommendable=false 상품, 조건표에 없는 문서(약관) | – |
| 상품 종류 | 요청과 다른 예금/적금 | – |
| 외국인 | foreignerEligible=false일 때만 | null |
| 비자 | visaTypes에 프로필 비자 없음 | null |
| 나이 | ageMin·ageMax 중 있는 값 밖 | 둘 다 null |
| 체류 기간 | 가장 짧은 계약기간(termOptions 최소, 없으면 termMonthsMin) > 남은 체류 개월 | 기간 null |
| 월 여유자금 | 적금의 월 최소액 > 월 여유자금. 예금은 비교하지 않음(월 흐름과 목돈은 단위가 다름) | 적금 월 최소액 null |
| 요청 기간 | 가장 짧은 계약기간 > 요청 상한 | 기간 null |
| 요청 월 납입액 | 납입 범위 밖(noLimit 상한은 통과). 요청액 > 월 여유자금이면 모든 상품 위반 | 월 범위 null |
| 적립 방식 | savingType이 요청과 다름 | null |

- gold 후보 = 위반 없음 + 요청 조건(요청 기간·월 납입액·적립 방식)에 판정 불가 없음 + goldRequires 충족.
  프로필 조건(나이·비자)의 판정 불가는 gold에서 빼지 않는다.
- Recall@5 = |상위 5 ∩ gold| / min(|gold|, 5), gold가 있는 26문항 평균.
- gold 0개 문항 기권율 = gold 0개 문항 중 아무것도 추천하지 않은 비율.

## 6. 해석

- 검색만으로는 프로필을 볼 수 없어서 체류 기간 위반(40)이 가장 많다. 남은 체류가 짧은 P1·P2·P4에 몰려 있고,
  P2(5개월)는 R1·R4에서 gold를 하나도 맞히지 못했다.
- 요청 조건 중 '3개월 이하'(R2)는 검색이 기간을 구분하지 못해 6·12개월 상품 3개를 함께 올린다.
- 추천 대상이 아닌 쏠편한 선물하는 적금이 적금 요청 세 개(R1·R4·R6)에 모두 들어간다.
- gold 0개 문항 4개에서 기준선은 언제나 5개를 추천한다(기권 0/4).
- R3·R5의 Recall@5 1.000은 gold가 작고(1~4개) 상품 종류가 검색어와 잘 맞아서다. 예금 조건(최소 가입액)은
  이번 판정에서 쓰지 않았다.

## 7. 한계

- 한 달부터 적금은 한도가 주·일 단위라 월 납입 요청(R4)에서 판정 불가로 gold에서 제외.
- foreignerEligible의 inferred(12개)는 해석이다. 위반은 false일 때만 세므로 외국인 조건 위반은 구조상 0이다.
- visaTypes가 모두 null이라 비자 조건은 전부 판정 불가(150)다.
- 예금은 월 여유자금과 비교하지 않는다. 프로필에 목돈 값이 없어 예금 최소 가입액 조건을 적용하지 않았다.
- 같은 요청이면 프로필이 달라도 추천이 같다(기준선은 검색어만 씀). 프로필별 차이는 gold와 판정에서만 생긴다.
- 30문항, 결정적 1회. 통계 검정은 하지 않았다.

## 8. 공개 목록

- 측정 뒤 평가기 수정: 없음.
- 측정 전 결정(사용자 확인): 조건표 수정(foreignerEligible 3단계, termOptions, recommendable,
  S드림 비대면 최소액), 프로필 수정(P2 체류 6→5개월, P5를 P3 체류 + 만 40세로), R2 6개월→3개월,

## 9. ②③ 비교 설계와 성공 기준 (측정 전 고정, 2026-11-16 태건 확정)

### 9-1. 비교안

| 안 | 후보 | 조건 | 순위 | 남는 상품이 없을 때 |
|---|---|---|---|---|
| ① 기준선 | ③ 검색 RRF 후보(dense 20 + BM25 20 청크) → 약관 제외 → 상품별 최고 점수 | 없음 | 검색 점수 | 항상 5개 |
| ② 검색 + 코드 필터 | ①과 같은 후보 풀 | 조건표로 위반이 확정된 상품 제외, 요청 조건 판정 불가도 제외 | 검색 점수 | 빈 목록 |
| ③ ② + 기권 이유 + explicit 우선 | ②와 같음 | ②와 같음 | foreignerEligible=explicit 먼저, 그다음 검색 점수 | 빈 목록 + 이유 코드 |

- 조건 입력: 정규식 파서를 쓰지 않고 구조화된 값으로 받는다. 형태는 챗봇 도구 인자와 같다
  (`productType`, `maxTermMonths`, `monthlyAmountKrw`, `accrual`(자유/정액), `requireForeignerExplicit`).
  오프라인 평가에서는 질문 세트의 요청 조건을 이 형태로 바꿔 넣는다. 실제 서비스는 영어 질문을 LLM이 도구 인자로
  채우는 구조이고, LLM이 인자를 맞게 채우는지는 챗봇 연결 단계에서 따로 잰다(그때 비용을 먼저 계산).
- 프로필(체류 만료·나이·월 여유자금·비자)은 구조화된 값으로 받는다.
- '외국인 가입 가능' 요청(`requireForeignerExplicit`)은 foreignerEligible=explicit만 인정한다(요청 조건).
- 판정 불가: 프로필 조건(나이·비자·월 여유자금)은 남기고 결과에 unknown으로 표시한다. 요청 조건(요청 기간·월 납입액·
  적립 방식)이 판정 불가인 상품은 제외한다(gold 정의와 같음).
- 후보 풀은 ①과 같게 고정한다. 풀에 없는 상품은 필터로 살릴 수 없다.
- 이유 코드(③, 남는 상품이 없을 때 하나): `REQUEST_EXCEEDS_SURPLUS`(요청 월 납입액 > 월 여유자금)
  → `STAY_TOO_SHORT`(체류 조건만 빼면 남는 상품이 있음) → `NO_MATCHING_PRODUCT`(그 밖) 순서로 정한다.

### 9-2. 성공 기준

| 기준 | 값 |
|---|---|
| gold Recall@5 | ① 0.791 이상, 그리고 ①보다 적중이 줄어든 gold 문항 0 |
| 기권 정확도 | gold 0개 문항 4개 모두 빈 목록(4/4) |
| 잘못된 기권 | gold가 있는 26문항 중 빈 목록 0(0/26) |
| 이유 코드 (③) | gold 0개 문항 4개 모두 expectedReason과 일치 |
| 보고만 함 | 후보 풀에 없어 놓친 gold 수 |

- ②와 ③이 모두 통과하면 기준 밖의 이유(챗봇이 추천이 없는 이유를 설명해야 함)로 ③을 고른다.

### 10-2. 해석과 한계

- Recall@5 1.000은 예상된 결과다. 필터가 gold와 같은 조건표·규칙을 쓰고, 후보 풀이 상품 13개 중 9~13개를 담아
  gold 상품이 모두 풀 안에 있었다(놓친 gold 0). 그래서 이 수치는 '조건이 맞게 들어오면 검색 풀이 gold를 놓치지 않는다'는
  확인이지, 추천 품질의 성과가 아니다.
- 풀 밖 상품은 요청과 다른 종류였다(적금 요청에서 예금, R3 예금 요청에서 땡겨요·한 달부터 적금). 상품이 늘면
  풀(dense 20 + BM25 20 청크)이 gold를 놓칠 수 있으니 이 수치는 계속 보고한다.
- 실제 서비스에서는 LLM이 영어 질문에서 도구 인자를 채운다. 인자가 틀리면 필터도 틀린다. 이 정확도는 챗봇 연결 단계에서 잰다.
- hold-out은 사용자가 준비되면 실행한다(선택에 쓰지 않음).
