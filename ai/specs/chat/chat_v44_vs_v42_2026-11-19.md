# 챗봇 프롬프트 v4.4 vs v4.2 측정 (#101, 2026-11-19)

## 판단

**운영 v4.4 전환 가능.**

- 운영은 지금 v4.2가 아니라 v4.1이다(6절). 그래서 전환하면 v4.1 → v4.4로 두 단계를 한 번에 넘는다.
  - v4.1 → v4.2(금융 정책 검색 추가)는 #90에서 쟀다(기존 49문항 × 3, 도구 일치 100%). v4.2 → v4.4는 이 문서다. 송금 30문항 세트는 v4.1로 잰 적이 없다.
  - 금융 정책 검색도 운영에서 처음 켜진다. 전환 뒤 `financePolicySearch` 상태와 금융 정책 질문을 꼭 확인한다(7절).
  - 전환은 서버 `.env`가 아니라 compose 기본값 변경(hanstep-backend #143)으로 한다(7절).
- 회귀가 없다. v4.2에서 통과하던 문항의 도구 선택·숫자 검사·송금 판정은 v4.4에서도 유지된다.
  - 엄격 규칙(base 전 회차 통과 → new 한 번이라도 실패)에는 3문항(S30·A02·A06)이 걸린다. 셋 다 도구 결과에 없는 상담 전화번호(관세청 125, 금감원 1332)를 적은 것이다.
  - v4.2도 같은 번호를 비슷하게(S30 10회 추가: v4.2 6/10, v4.4 7/10) 또는 더 많이(금융 정책 1332: v4.2 15회, v4.4 12회) 적었다. 그래서 버전 차이로 보지 않았다(5-1절).
- 환율 질문 36회:
  - `fx_rate_summary` 호출 36/36, `FX_SUMMARY_CARD` 36/36.
  - 숫자 검사 36/36, 기간별 방향 불일치 0.
  - 금지 표현 0(전체 423회차 기준).
- 송금 카드(REMITTANCE_CONFIRM)와 E-7-4 카드(E74_SCORE_CARD)는 v4.2와 같은 회차에서 같게 나왔다(60 = 60, 15 = 15).
- 지연 중앙값: 전체 +0.8%(첫 delta)·+0.9%(전체 시간). 환율 문항만 보면 +12.7%·+14.0%로, 둘 다 기준 +20% 이내다.
- 턴당 입력 토큰은 +8.8%(19,380 → 21,076)다.
- 미측정 1건. 금융 정책 답변의 내용 등급과 #93 위험 문장 검사기는 로컬에 문서 폴더가 없어 재지 못했다. 금융 정책 46문항의 도구 선택은 쟀고 두 버전이 같다. 그래서 전환 직후 확인(7절)에 금융 정책 질문 1개를 더 넣었다.

## 1. v4.4에서 바뀐 것 (develop `b19846d` 기준, 코드 수정 없이 확인)

- 프롬프트: `chat-v4.4` = v4.2 본문 그대로 + `app/chat/prompts/fx_rules.md`(끝에 절 추가). v4.2의 줄은 바꾸지 않는다(`_with_fx_rules`). v4.3a의 방향 규칙은 넣지 않았다.
- 도구: v4.4 = v4.2 도구(금융 분석·비자·송금·상품·금융 정책 검색) + `fx_rate_summary`. `FX_PROMPT_VERSIONS = {"v4.4"}`라 다른 버전에는 붙지 않는다.
- `fx_rules.md`의 규칙(요약)
  - 환율 질문(현재 값, 지난달·과거와 비교, 지금 보내도 되는지)은 `fx_rate_summary`를 먼저 부른다. 도구 호출 전에 글을 쓰지 않고, 이런 질문에 `get_fx_rate`를 쓰지 않는다.
  - 도구 결과의 숫자만 그대로 쓴다(계산·반올림·환산 금지).
  - 과거 평균과의 비교만 한다. 오를지 내릴지, 지금이 좋은 때인지 말하지 않는다. 예측·시점을 물으면 예측할 수 없다고 말하고 과거 비교를 준다.
  - `<unit> <currency> = <rate> KRW`로 쓰고, 원천·기준일(asOf)·평균마다 영업일 수를 함께 말한다.
  - MARKET_REF는 "market reference rate"(ECB 기반, 송금 환율 아님), KOREAEXIM은 "Korea Eximbank published rate"라고 부른다.
  - `isMock`이면 데모 데이터라고 말한다. `stale`이면 기준일·마지막 확인 시각을 강조한다. 데이터 부족 기간은 평균을 짐작하지 않는다. 도구 실패면 환율을 말하지 않는다. 마크다운 강조는 쓰지 않는다.
- `fx_rate_summary`(#94): Spring `GET /internal/v1/ai-context/users/{userId}/fx-summary?currency=`를 부른다. 인자는 `currency`(선택, 빼면 화면 통화 USD + 모국 통화)다. LLM에는 rate·source·asOf·lastCheckedAt·전일 대비·1/3/6/12개월 평균(차이·%·LOWER/HIGHER/SAME·영업일 수)·isMock·stale이 간다. 오류는 404 → `no exchange rate data`, 400 → 화면 통화 아님, 그 밖 → `data unavailable`이다.
- `FX_SUMMARY_CARD`(#100): `fx_rate_summary`가 SUCCEEDED이고 통화가 1개 이상이면 `agent.done.blocks`에 카드를 낸다.
  - 한 턴에 여러 번 불러도 통화 기준으로 카드 1개로 합친다. 같은 통화는 나중 값을 쓰고, 순서는 처음 나온 순서다.
  - 필드: currency·unit·rate·sendRate·receiveRate(KOREAEXIM만, 그 밖에는 null)·change·changeRate·source·asOf·fetchedAt·periodAverages[period·avg·diff·diffRate·direction·businessDays]·isMock·stale, unavailableCurrencies.
  - 데이터 부족 기간은 카드에서 뺀다.
  - 실패(FAILED·REJECTED·TIMEOUT·INVALID_RESPONSE)이거나 카드 형식이 어긋나면 카드를 내지 않는다.
  - 버튼은 FE가 고정으로 붙인다.
- 숫자 검사(#94, 측정 전용): 음수의 절댓값을 근거로 인정하는 것은 `fx_rate_summary` 결과에만 적용한다. 날짜 판정도 고쳐서, 1406.51 같은 소수를 날짜로 읽지 않는다.
- 이미 있던 측정
  - #94 본문의 표는 지워진 v5(v4.1 + 같은 fx_rules)로 받은 답변이다(10문항 × 1회). v4.4는 아무도 재지 않았다.
  - #100 PR 본문의 머지 조건 "v4.4 측정 통과 뒤 머지"는 측정 없이 머지됐다.
  - 금융 정책 46문항은 태건님이 v4.2로 쟀다(`specs/rag/reviews/finance_policy_merged_v4_2_review.md` 등). 이 PC에는 그 원자료와 금융 정책 문서 폴더가 없다.
  - eval·송금 세트를 v4.2로 잰 기록은 없다.
  - 그래서 v4.2와 v4.4를 같은 조건에서 나란히 새로 쟀다.

## 7. 운영 전환

운영 프롬프트 버전은 서버 `deploy/.env`에 두지 않고 compose 기본값으로 정한다(서버 `.env` 주석). 그래서 `.env`를 고치지 않고, hanstep-backend #143 PR로 `deploy/compose.prod.yml`의 기본값을 `v4.1` → `v4.4`로 바꾼다.

- 그 PR을 develop에 머지하면 자동 배포(`deploy-prod` → `auto-deploy.sh`)가 ai-server를 새 값으로 다시 만든다. **머지가 곧 전환이다.**
- AI 코드 기본값(`config.py`의 `v4.1`)은 바꾸지 않는다. compose가 늘 값을 넘기므로 운영에는 효과가 없고, 로컬 개발 기본값만 바뀐다.
- 서버 `.env` 주석의 "AI 코드 기본값을 따른다"는 실제로는 "compose 기본값을 따른다"다. 주석만 고친다.

alias dc='docker compose -f deploy/compose.prod.yml'

# 0. #143 머지 전: AI 코드가 v4.4를 아는지(b19846d 이상), 지금 버전(v4.1), .env에 줄이 없는지
git -C ~/hanstep/hanstep-AI log -1 --format='%h %s'
dc exec ai-server python -c "from app.chat.prompts import PROMPT_VERSIONS; print('v4.4' in PROMPT_VERSIONS)"

grep -n 'CHAT_PROMPT_VERSION' deploy/.env

# 0-1. 금융 정책 검색이 처음 켜지므로 문서 폴더와 설정을 확인한다
