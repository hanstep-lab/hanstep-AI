# 챗봇 답변 표시 규칙 v1(#116, 프롬프트 v4.6)

- **v4.6 = v4.5 + 표시 규칙 + 상품 카드 표시 규칙(#119).** 이 규칙을 쓰는 정식 버전이다. 도구 묶음은 v4.5와 같다(환율 진단·상품 추천 카드 포함).
- **v4.4d = v4.4 + 표시 규칙(11/20 측정).** 1차 측정을 재현하려고 남긴 갈래다. 운영에는 쓰지 않는다.
- 두 버전의 표시 규칙 글(`display_rules_ko.md`·`display_rules_en.md`)과 바뀌는 줄(`DISPLAY_CHANGES`)은 같다.
- 상품 카드 표시 규칙(`display_product_card_ko.md`·`display_product_card_en.md`)과 상품 규칙 두 줄 변경(`PRODUCT_CARD_CHANGES`)은 v4.6에만 있다. v4.4d에는 상품 카드가 없어서 넣지 않았다(1차 측정 재현용 해시 그대로).

챗봇 답변의 구조, 숫자, 통화 표기 규칙이다. 숫자 표시는 코드(`app/chat/display.py`)가 만들고 LLM은 그대로 옮긴다. 표시 규칙은 챗봇 공통 코드에서 관리한다(챗봇 담당 이태건 허락). 환율 도구(`fx_rate_summary`)에 먼저 적용했다.

## 규칙

1. 답변 언어
   - 사용자 설정이 ko면 한국어, en이면 영어로 답한다.
   - vi·zh는 고려·테스트하지 않는다. 답변 언어는 지금처럼 프롬프트의 `{language}`를 따르고, 숫자·통화 표기만 en 규칙을 쓴다.
2. 구조
   - 첫 줄: 결론 한 문장. 볼드(`**…**`)는 이 문장에만 쓴다.
   - 근거 숫자: `- ` 목록
   - 마지막 한 줄: 출처·기준 시각과 주의 문구
   - 같은 화면 카드에 나온 값을 문장에서 길게 반복하지 않는다.
     - 환율 카드: 현재 환율, 전 영업일 대비
     - 송금 확인 카드: 금액, 수수료, 환율
     - 상품 추천 카드(v4.6, #119): 상품 이름·종류·기간·금액 범위·금리. 아래 6번
   - 내부 계산 근거(평균의 영업일 수 등)는 답변에서 뺀다.
3. 숫자. 반올림·버림·쉼표는 코드에서 하고, LLM은 숫자를 바꾸지 않는다.
   - 원화 금액(송금액, 수수료, 받는 금액, 소득·지출): 정수, 원 미만 버림(0 쪽으로), 천 단위 쉼표
   - 환율과 평균 환율: 앱 환율 카드와 같은 통화별 자릿수(USD 2, PHP 3, 그 밖 2)로 반올림(ROUND_HALF_UP)
     - 공식 고시는 값이 그대로 나온다(1,330.80).
     - 평균은 반올림한다(1335.4375 → 1,335.44).
   - 변동값(전 영업일 대비, 평균과의 차이)은 부호를 붙인다: `-1.08`, `+0.112`. 반올림해서 0이면 `0.00`.
4. 통화 표기(같은 화면 카드 표기와 맞춤)
   - 한국어
     - 원화는 "원"만 쓴다(1,330.80원). KRW·(KRW)·₩은 쓰지 않는다.
     - 외화는 답변에서 처음 한 번만 "미국 달러(USD)"로 쓰고, 그다음은 "달러"로 쓴다. 필리핀 페소(PHP)·페소, 베트남 동(VND)·동도 같다.
     - 표에 없는 통화는 코드만 쓴다.
   - 영어
     - 통화 코드를 쓴다.
     - 환율은 `1 USD = 1,330.80 KRW`, 금액은 `KRW 700,000`으로 쓴다.
5. 예(한국어, 환율 평균 질문)

   ```
   **오늘 미국 달러(USD) 환율은 1,330.80원으로, 최근 1년 평균보다 낮아요.**
   - 1개월 평균 1,335.44원
   - 3개월 평균 1,351.03원
   - 6개월 평균 1,421.75원
   - 1년 평균 1,446.04원
   한국수출입은행 고시 · 11월 20일 10:42 기준이에요. 과거 평균과 비교한 것이고, 앞으로의 환율을 예측하지는 않아요.
   ```
6. 상품 추천 카드 답변(v4.6만, #119)
   - 카드(`PRODUCT_RECOMMEND_CARD`)가 상품마다 이름·종류·기간·금액 범위·기본/최고 금리를 보여 준다. 본문은 상품을 다시 나열하지 않는다.
   - 상품이 있을 때
     - 첫 줄(볼드): 맞는 상품 수(낱말로: three, 세 개)와 주된 이유(남은 체류 기간, 월 여유자금 등)
     - 카드에 없는 내용만 두 문장 이내, 목록 없이: 확인하지 못한 조건(`notChecked`: 비자·나이·남은 체류·여유자금), 금리·우대 조건은 카드에 있다는 안내
     - 마지막 줄: 출처(신한은행 상품설명서)와 `asOf`
   - 순서를 변명하지 않는다("which is not a quality ranking" 같은 문장). 순서를 말해야 하면 "listed by the conditions you meet"(ko "조건에 맞는 순서예요")만 쓴다.
   - 상품이 없을 때(기권: `products`가 비고 `abstainReason`만): 첫 줄에 이유(상품 규칙대로), 다음 줄에 다음 행동 하나(기간·금액을 바꿔 다시 묻기 등)
   - 상품 수를 낱말로 쓰게 한 것은 수를 세어 만든 숫자가 number_check에서 근거 없는 숫자로 잡히지 않게 하려는 것이다.
   - 예(한국어)

   ```
   **남은 체류 기간 14개월 안에 끝나는 정기예금 세 개를 찾았어요.**
   상품설명서에 비자·나이 조건이 없어서, 가입할 수 있는지는 신한 앱이나 영업점에서 확인해 주세요. 금리와 우대 조건은 카드에서 볼 수 있어요.
   신한은행 상품설명서 · 2026-11-02 기준이에요.
   ```

## FE 표식 계약(볼드)

앱 채팅 말풍선은 2026-11-20 기준 마크다운을 그리지 않는다(`hanstep-frontend` `src/app/(tabs)/chat.tsx`의 `<Text>{msg.text}</Text>`). 그래서 v4.6 답변의 `**`는 FE가 처리하기 전까지 글자 그대로 보인다. **운영을 v4.6으로 바꾸기 전에 FE 처리가 먼저 나가야 한다**(FE 이슈 hanstep-lab/hanstep-frontend#58).

- 표식은 하나뿐이다. AI 답변 본문(`agent.delta` 이어 붙인 글, 대화 기록의 `content`)에서 같은 줄 안의 `**…**` 쌍만 굵게 그린다.
- 그 밖의 마크다운(`#`, `*`, `_`, 링크, 표)은 프롬프트가 쓰지 못하게 한다. FE는 해석하지 않는다.
- 목록 `- `는 평문 줄 그대로 보여도 된다(줄바꿈은 지금도 그대로 보인다).
- 숫자 목록 `1. `은 표시 규칙에는 없다. 다만 기존 비자 규칙(E-7-4 개선 단계)과 열린 조언 질문에서 나올 수 있다(2차 측정 v4.6 V05 4회 중 3회). 평문 줄로 보여도 된다.
- 측정 답변 69개(1차 v4.4d 30개, 2차 v4.6 39개)에서 확인한 것
  - `**` 쌍은 모두 첫 줄에 하나뿐이다.
  - 제목·표·링크·코드·기울임·`*` 목록·들여쓴 목록은 0건이다.
- 모든 AI 메시지에 같은 규칙을 쓴다.
  - 스트림에는 프롬프트 버전 신호가 없다.
  - v4.5 이하는 볼드 금지라 `**`가 나오지 않는다.
- 스트리밍 중 닫히지 않은 `**`는 닫힐 때까지 평문으로 두고, 닫히면 굵게 바꾼다.

## number_check와의 관계

검사 기준은 바꾸지 않았다.
- `number_check`는 쉼표·소수·`원`·`KRW`가 붙은 숫자를 같은 값으로 읽는다. `1,330.80원`, `1,330.8원`, `1 USD = 1,330.80 KRW`는 모두 1330.8이다.
- 반올림한 평균(`1,335.44`)은 원래 값(1335.4375)만 있으면 근거가 없다고 나온다. 표시 문자열이 도구 결과에 있으면 근거가 있다. 측정 스크립트가 도구 결과의 문자열 속 숫자도 허용값에 넣기 때문이다.

## 알려진 차이

- 앱 카드의 `fmtFxRateByCurrency`는 JS 부동소수점으로 반올림한다. x.xx5 경계 일부(예: 1.005)에서 카드는 `1.00`, 답변은 `1.01`이 된다. 서버 평균은 소수 넷째 자리라 드물다. FE를 고치면 맞춰진다.
- 앱 카드는 출처를 "수출입은행 고시"로, 통화를 "미국 USD"로 쓴다. 답변은 위 규칙대로 "한국수출입은행 고시", "미국 달러(USD)"로 쓴다.
- 앱 카드에는 기준일만 있다(fetchedAt 시각은 쓰지 않음). 답변 마지막 줄은 확인 시각이 기준일과 같은 날이면 시각까지 쓴다(`basisText`).
- 앱에는 다국어 처리가 없다. 영어 사용자 화면에서도 카드는 "원"으로 나온다. 영어 답변은 규칙대로 `KRW`를 쓴다.
- #114(이태건, PR #118)의 v4.5가 먼저 머지됐다. 표시 규칙은 그 위로 옮겨 v4.6으로 정리했다. 1차 측정 기록의 v4.4d 이름은 그대로 둔다.

v4.4d = v4.4 + 표시 규칙. 2차 측정(v4.5 → v4.6)은 아래 "2차 측정" 절에 있다.

**결론**
- v4.4d는 규칙 준수율이 크게 올랐다.
  - 결론 첫 줄: ko 93%, en 80%

  - 소수 자리·쉼표(환율 도구 회차): 100%

- 대신 첫 글자 지연이 늘었다: ko +2.1초, en +0.7초. 마지막 LLM 호출의 출력 토큰(thinking 포함)이 늘었기 때문이다(아래 "지연" 표).
